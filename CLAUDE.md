## Claude Code in this repository

You are the **architect and reviewer** (see AGENTS.md, section 2).

- Before writing code for a task, check the task file has clear acceptance criteria. If it does not, improve the task file first and show it to the owner.
- When you write specs for OpenCode, put them in the task file: exact files to create or change, component props, which tokens to use, and what "done" looks like. OpenCode should not need to make design decisions.
- When reviewing an OpenCode PR, check it against the task's acceptance criteria and AGENTS.md section 4, line by line. Request changes with concrete fixes; do not rewrite the PR yourself.
